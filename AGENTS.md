# AGENTS.md

Guidance for AI coding agents working in this repository. Human contributors follow the same rules.

## What this repository is

BoardKit is a document engine in which the text source is the state. Plain Markdown is the source of truth. Writes arrive as full text or as patches and go through one commit pipeline. Any number of projections derive from the same source. Every change is recorded as an event. Includes pull several documents into one. The engine is writer-agnostic (humans, agents and programs all write) and consumer-agnostic (LLMs, browsers and mail clients all read).

It is a pnpm monorepo: published packages in `packages/`, a private workbench server in `apps/demo`, runnable examples in `examples/`, user docs in `docs/`. [CONTRIBUTING.md](CONTRIBUTING.md) lists the packages.

Coding standards, dependency rules and test conventions: see [CONTRIBUTING.md](CONTRIBUTING.md).

## Commands

Run everything from the repository root, in this order:

```bash
corepack enable
pnpm install
pnpm build        # must run before typecheck and test
pnpm typecheck
pnpm test
pnpm lint
```

For a single package:

```bash
pnpm --filter @onioneko/boardkit-core test
pnpm --filter @onioneko/boardkit-core typecheck
```

## Module map

`packages/core/src`:

| Module | Responsibility |
|---|---|
| `model/` | Document model: branded ids, diagnostics, inline refs, sections, blocks, parsed docs, frontmatter shape validation |
| `parse/` | Markdown to `ParsedDoc`: sections with anchors and slugs, `{{source}}` and `{{include}}` recognition, fenced block extraction, fail-soft diagnostics |
| `ports/` | Replaceable boundaries (Storage, Lock, EventSink, Clock, Source) with filesystem and in-memory adapters |
| `link/` | Include-graph resolution (reachable docs, cycle detection, target existence, reverse include index) and the merged tree |
| `validate/` | Block attrs: static JSON Schema, cross-field hooks, bounded-history truncation |
| `resolve/` | Value resolution: request deduplication, bounded concurrency, stale degradation |
| `project/` | Projection: the shared merged-tree walk (`walk.ts`) and the built-in `text` projector |
| `blocks/` | Block framework: type definitions, transitions, affordances |
| `write/` | Commit pipeline (VALIDATE, LOCK, COMMIT, DIFF, EMIT), patches, concurrency guards |
| `diff/` | Structural diff and event synthesis |
| `watch/` | External write detection |
| `middleware/` | Write and projection middleware chains |
| `intent/` | Affordance decoding and the default intent route |
| `engine/` | Engine assembly, document versioning, event subscription and replay |
| `internal/` | The `@onioneko/boardkit-core/internal` entry point: pipeline internals with no stability guarantee |

The public API of each package is its `src/index.ts`. The `html` projector lives in `packages/html`, not in core.

## Scope

- Change only what the task needs. Do not refactor, rename or reformat unrelated code.
- Do not change root configuration (`tsconfig.base.json`, `biome.json`, `pnpm-workspace.yaml`, workflows) unless the task is about it.

## What done means

- `pnpm build`, `pnpm typecheck` and `pnpm test` pass.
- `pnpm lint` reports nothing new in the files you changed.
- New behavior has tests written first, following the test-first process in CONTRIBUTING.md.
- A change to a published package has a changeset ([CONTRIBUTING.md](CONTRIBUTING.md#changesets)).
- Your summary lists the files you changed, which test covers which behavior, and anything you could not verify.

## Do not

- Edit `docs/api` by hand. It is generated by `pnpm docs:api`.
- Edit or commit `dist/` output.
- Publish packages or bump versions in `package.json`. Releases come from changesets through CI.
